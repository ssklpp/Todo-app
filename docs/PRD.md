# PRD - Todo App (초안)

> 출처: `docs/IDEA.md`
> 상태: 초안 (검토 필요)

## 1. 목표

혼자 쓰는 간단한 할 일 목록 웹 앱을 만든다.

- 사용자가 할 일을 빠르게 적고, 확인하고, 끝낸 일을 표시하고, 지울 수 있다.
- 브라우저를 새로고침해도 할 일이 사라지지 않는다.
- 기능은 MVP로 제한해 초보자가 단계별로 만들며 배울 수 있게 한다.

## 2. 대상 사용자

- 자기 할 일을 혼자 관리하는 개인 사용자 1명
- 로그인이나 다른 사람과의 공유가 필요 없는 사용자
- 복잡한 기능보다 단순하고 빠른 사용을 원하는 사용자

## 3. 기능 목록

| ID | 기능 | 설명 |
| --- | --- | --- |
| F-01 | 할 일 추가 | 제목을 입력해 할 일을 추가한다. 제목은 필수이며 1~100자다. |
| F-02 | 할 일 목록 보기 | 할 일 전체를 최신순(최근에 추가한 것이 위)으로 보여준다. |
| F-03 | 완료/미완료 전환 | 체크박스로 할 일의 완료 상태를 바꾼다. |
| F-04 | 할 일 삭제 | 할 일을 목록에서 삭제한다. |
| F-05 | 데이터 유지 | 새로고침해도 할 일과 완료 상태가 그대로 남는다. |

### 기능별 조건

- **F-01**
  - 제목이 비어 있으면 추가하지 않는다.
  - 제목이 100자를 넘으면 추가하지 않는다.
  - 추가한 할 일은 미완료 상태로 시작한다.
- **F-02**
  - 할 일이 하나도 없을 때의 화면 처리가 필요하다. (세부 내용은 COMPONENT_SPEC에서 정한다.)
- **F-03**
  - 완료 ↔ 미완료를 여러 번 바꿀 수 있다.
- **F-05**
  - F-01, F-03, F-04로 바뀐 내용이 모두 유지된다.

## 4. 사용자 스토리

| ID | 관련 기능 | 사용자 스토리 |
| --- | --- | --- |
| US-01 | F-01 | 사용자로서 해야 할 일을 제목만 적어 빠르게 추가하고 싶다. 잊지 않기 위해서다. |
| US-02 | F-01 | 사용자로서 제목을 비우거나 너무 길게 쓰면 추가되지 않기를 원한다. 목록이 깔끔하게 유지되도록. |
| US-03 | F-02 | 사용자로서 최근에 추가한 할 일을 맨 위에서 보고 싶다. 새 일을 바로 확인하기 위해서다. |
| US-04 | F-03 | 사용자로서 끝낸 일을 체크해 완료로 표시하고 싶다. 무엇을 끝냈는지 알기 위해서다. |
| US-05 | F-03 | 사용자로서 잘못 체크한 일을 다시 미완료로 되돌리고 싶다. |
| US-06 | F-04 | 사용자로서 필요 없어진 할 일을 삭제하고 싶다. 목록을 정리하기 위해서다. |
| US-07 | F-05 | 사용자로서 새로고침해도 내 할 일이 남아 있기를 원한다. 다시 입력하지 않기 위해서다. |

## 6. 성공 기준

- F-01 ~ F-05가 모두 동작한다.
- 1자, 100자 제목은 추가되고, 빈 제목과 101자 제목은 추가되지 않는다.
- 목록이 항상 최신순으로 표시된다.
- 체크박스를 누르면 완료 상태가 바로 화면에 반영된다.
- 삭제한 할 일은 목록에서 바로 사라진다.
- 추가, 완료 전환, 삭제 후 새로고침해도 결과가 그대로다.
- 각 기능에 대한 테스트(`docs/TEST_CASES.md`)가 모두 통과한다.

## 7. 확인이 필요한 사항

- **v0.1 데이터 유지 방식:** 로드맵의 v0.1은 "브라우저 메모리"인데, F-05는 새로고침 후 유지를 요구한다. 순수 메모리는 새로고침하면 사라진다. v0.1에서 F-05를 제외할지, `localStorage`를 쓸지 정해야 한다.
- **공백만 있는 제목:** `"   "`처럼 공백만 있는 제목을 빈 제목으로 볼지 정해야 한다. 앞뒤 공백을 제거한 뒤 1~100자를 검사할지도 함께 정한다.
- **삭제 확인:** 삭제 전에 확인 창을 띄울지 정해야 한다. IDEA.md에는 언급이 없다.
