# COMPONENT_SPEC - Todo App (초안)

> 출처: `docs/PRD.md`, `docs/API_SPEC.md`
> 상태: 초안 (검토 필요)

## 1. 개요

- 화면은 한 페이지(`/`)뿐이다.
- 컴포넌트는 `src/components/`에 둔다. 페이지는 `app/page.tsx`다.
- 할 일 타입 `Todo`는 `DATA_MODEL.md` 4절의 것을 쓴다.
- API는 FastAPI 서버(`NEXT_PUBLIC_API_URL`)에 있다. Next.js API 라우트는 쓰지 않는다. (TRD 4절)
- 이 문서는 v0.2 이후 기준이다. v0.1과 다른 점은 6절에 적는다.

## 2. 컴포넌트 트리

```text
app/page.tsx (HomePage)
└─ TodoApp            할 일 목록 상태를 갖고 API를 부른다
   ├─ TodoForm        제목 입력창 + 추가 버튼
   ├─ (상태 문구)      로딩, 에러, 빈 목록 문구
   └─ TodoList        할 일 목록
      └─ TodoItem     할 일 하나 (체크박스 + 제목 + 삭제 버튼)
```

| 컴포넌트 | 하는 일 | 관련 기능 |
| --- | --- | --- |
| `HomePage` | `TodoApp`을 화면에 놓는다. 다른 일은 하지 않는다. | - |
| `TodoApp` | 목록 상태를 갖는다. API를 부르고 결과로 목록을 바꾼다. 로딩과 에러 문구를 보여준다. | F-01 ~ F-05 |
| `TodoForm` | 제목을 입력받고 검사한 뒤 `TodoApp`에 알린다. | F-01 |
| `TodoList` | 할 일 배열을 받아 `TodoItem`을 여러 개 그린다. 빈 목록 문구를 보여준다. | F-02 |
| `TodoItem` | 할 일 하나를 그린다. 체크와 삭제를 `TodoApp`에 알린다. | F-03, F-04 |

- API를 부르는 곳은 `TodoApp` 하나뿐이다. 나머지는 받은 값을 그리고, 사용자 동작을 위로 알리기만 한다.

## 3. Props 타입

Props는 부모 컴포넌트가 자식에게 넘겨주는 값이다.

```ts
import type { Todo } from "@/types/todo";

// HomePage, TodoApp: 받는 값 없음

// 제목 입력창 + 추가 버튼
type TodoFormProps = {
  onAdd: (title: string) => Promise<void>; // 검사를 통과한 제목을 넘긴다
};

// 할 일 목록
type TodoListProps = {
  todos: Todo[]; // 최신순으로 정렬된 배열
  onToggle: (id: string, completed: boolean) => Promise<void>; // 바뀐 뒤의 완료 여부를 넘긴다
  onDelete: (id: string) => Promise<void>;
};

// 할 일 하나
type TodoItemProps = {
  todo: Todo;
  onToggle: (id: string, completed: boolean) => Promise<void>;
  onDelete: (id: string) => Promise<void>;
};
```

- 함수 Props가 `Promise`를 돌려주는 이유: 자식이 API 요청이 끝날 때까지 기다렸다가 버튼을 다시 켤 수 있다.
- `onToggle`이 바뀐 뒤의 값을 받는 이유: API_SPEC 3.3의 `PATCH` 요청이 그 값을 보내기 때문이다.

## 4. 사용자 동작과 결과

| ID | 사용자 동작 | 결과 | 관련 기능 / API |
| --- | --- | --- | --- |
| A-01 | 페이지를 연다 | 로딩 문구가 보인다. 목록을 받으면 최신순으로 보인다. | F-02, F-05 / `GET /api/todos` |
| A-02 | 제목을 입력하고 "추가" 버튼을 누른다 | 목록 맨 위에 새 할 일이 미완료로 보인다. 입력창이 비워진다. | F-01 / `POST /api/todos` |
| A-03 | 입력창에서 Enter 키를 누른다 | A-02와 같다. | F-01 |
| A-04 | 제목을 비운 채 추가한다 | 추가되지 않는다. 입력창 아래에 검사 문구가 보인다. 서버로 보내지 않는다. | F-01 |
| A-05 | 101자 이상 제목으로 추가한다 | A-04와 같다. 문구만 다르다. | F-01 |
| A-06 | 미완료 할 일의 체크박스를 누른다 | 체크 표시가 생긴다. | F-03 / `PATCH /api/todos/{id}` |
| A-07 | 완료 할 일의 체크박스를 누른다 | 체크 표시가 사라진다. | F-03 / `PATCH /api/todos/{id}` |
| A-08 | "삭제" 버튼을 누른다 | 그 할 일이 목록에서 사라진다. | F-04 / `DELETE /api/todos/{id}` |
| A-09 | 새로고침한다 | A-01과 같다. 바꾼 내용이 그대로 보인다. | F-05 |

### 동작 규칙

- **응답을 받은 뒤에 화면을 바꾼다.** 서버가 성공했다고 답한 다음에 목록을 바꾼다. 요청이 실패하면 화면은 그대로 둔다.
- **요청 중에는 버튼을 끈다.** 같은 요청이 두 번 가지 않게 한다.
  - 추가 중: "추가" 버튼이 꺼지고 글자가 "추가 중..."으로 바뀐다.
  - 체크나 삭제 중: 그 할 일의 체크박스와 "삭제" 버튼이 꺼진다.
- **입력창에 글자 수 제한(`maxLength`)을 걸지 않는다.** 걸면 101자를 입력할 수 없어서 A-05의 검사 문구를 볼 수 없다.
- **삭제 확인 창은 띄우지 않는다.** PRD 7절 미결 사항이다. 정해질 때까지 PRD에 있는 대로 바로 삭제한다.

### 접근성 (스크린 리더와 테스트를 위해)

- 입력창 이름: "할 일 제목"
- 체크박스 이름: 할 일 제목 (예: "우유 사기")
- 삭제 버튼 이름: "{제목} 삭제" (예: "우유 사기 삭제")
- 이름이 있으면 React Testing Library로 버튼과 체크박스를 이름으로 찾을 수 있다.

## 5. 상태별 문구

### 목록 상태 (`TodoApp`, `TodoList`)

| 상태 | 언제 | 보여줄 문구 | 보여주는 곳 |
| --- | --- | --- | --- |
| 로딩 | 페이지를 열고 목록을 받기 전 | 할 일을 불러오는 중입니다... | 목록 자리 |
| 빈 목록 | 목록을 받았는데 할 일이 0개 | 아직 할 일이 없습니다. 위에서 할 일을 추가해 보세요. | 목록 자리 |
| 목록 읽기 실패 | `GET` 요청이 실패함 | 할 일을 불러오지 못했습니다. 새로고침해 주세요. | 목록 자리 |

### 입력 검사 문구 (`TodoForm`)

API_SPEC 3.2의 message와 같은 문구를 쓴다.

| 상황 | 보여줄 문구 |
| --- | --- |
| 제목이 비어 있음 | 제목을 입력해 주세요. |
| 제목이 100자 초과 | 제목은 100자 이하로 입력해 주세요. |

- 사용자가 입력창에 다시 글자를 쓰면 검사 문구를 지운다.

### 동작 실패 문구 (`TodoApp`)

추가, 체크, 삭제 요청이 실패하면 입력창 위에 문구를 보여준다.

| 상황 | 보여줄 문구 |
| --- | --- |
| 서버가 에러 응답을 보냄 | 에러 응답의 `message`를 그대로 보여준다 (API_SPEC 2절) |
| 서버에 연결하지 못함 (응답이 없음) | 서버에 연결하지 못했습니다. 잠시 후 다시 시도해 주세요. |

- 다음 동작이 성공하면 실패 문구를 지운다.

## 6. v0.1에서 다른 점

- v0.1에는 API가 없다. `TodoApp`이 목록을 React 상태에만 둔다.
- 그래서 로딩 문구, 목록 읽기 실패 문구, 동작 실패 문구, "추가 중..." 표시는 쓰지 않는다.
- `id`와 `createdAt`은 `TodoApp`이 직접 만든다.
- 새로고침 후 데이터를 유지하는 방법(F-05)은 PRD 7절 미결 사항이다.

## 7. 확인이 필요한 사항

- **목록 읽기 실패 시 다시 시도 버튼:** 지금은 "새로고침해 주세요" 문구만 둔다. 버튼을 둘지 정해야 한다.
- **완료된 할 일의 모양:** 지금은 체크 표시만 바뀐다. 취소선 같은 표시를 더할지 정해야 한다.
- **공백만 있는 제목, 이모지 글자 수:** PRD 7절, DATA_MODEL 6절 미결 사항이다. 정해지면 4절 A-04, A-05와 5절 문구를 다시 맞춘다.
